## 一、这是个什么东西？

### 大白话

你在自己的电脑（或一台服务器）上跑一个小程序。它的作用是把「在 DeepSeek 网页版上聊天」这件事，变成一个**正规的 AI 接口**。

变成接口之后，你手上那些 AI 工具——写代码的 Claude Code、聊天面板 Cherry Studio、Open WebUI、Cline、LibreChat、LobeChat、Dify，以及任何「能填一个 API 地址和一把密钥」的软件——就都可以连到这个小程序上，像调用付费官方 API 那样工作：能流式输出、能工具调用、能记长对话。区别只在于，**流量走的是 DeepSeek 网页版的免费额度，不需要官方 API Key**。

打个比方：DeepSeek 网页版原本只有「给人点的界面」，这个程序给它接了一根「给程序用的线」。你的工具插上这根线就能说话；而网页那边看到的是一个正常的浏览器会话。

### 术语

DeeperSeeker 是一个**自托管的反向代理网关（self-hosted reverse-proxy gateway）**。

- 它持有你的 DeepSeek 网页会话凭据（token，会话 JWT），代表浏览器与聊天后端通信；
- 对外暴露标准协议端点：OpenAI Chat Completions（`/v1/chat/completions`）与 Anthropic Messages（`/v1/messages`），并附带 `/v1/responses`、`/v1/models`、`/v1/files` 等兼容端点；
- 内部负责会话映射（session mapping）、PoW 挑战求解、多账号池轮转（pool rotation）、上游故障转移（failover）、上下文滚动压缩（summarize-and-rollover）、工具调用解析与修复；
- 凭据、用量、会话都落在本地数据库里，默认不离开本机。

一句话概括：**网页版免费额度 + 官方 API 的接入体验。**

### 它能做什么、不能做什么

| 能 | 不能 / 不保证 |
|---|---|
| 把 OpenAI / Anthropic 兼容客户端接到 DeepSeek 网页免费层 | 不提供官方 API Key，也不等价于官方付费 API 的配额与稳定性 |
| 流式与非流式输出、工具调用、长对话接续 | 上游（DeepSeek）本身改协议、限速、维护时，这边无法凭空消除 |
| 多账号自动轮转、失效自动隔离 | 不能让一个已被封禁的账号复活，令牌死了要重新提取 |
| 本地保存令牌池、会话、用量 | 默认不外发；只有你主动开启备份目标，数据才会离开本机 |
| 中英双语面板与文档 | 不承诺账号绝对安全——自动化使用违反 DeepSeek 服务条款，风险自负 |

> **一个具体的优点，配具体的场景**（不喊「稳定」这种空话）：很多接入方案在你让模型自己跑一个长任务、你没盯着的时候，中途悄悄断了、或者答到一半停下，你忙完回来才发现任务根本没做完，还得从头再来，很耽误事。这个项目专门处理了这类「跑到一半出问题」的情况——上游瞬时抽风、流突然断掉、模型停在中途，都会自动续上并接着把结果收回来（术语见第五章的「空流自动续写」「故障转移」）。它不是保证「永不出错」，而是把「出错就前功尽弃」变成「多数情况下能自己接回来」。

### 开始前你需要准备

1. 一台能长期开着的机器（本机、NAS、VPS、免费托管平台均可）；
2. Python 3.11 或更新版本（项目在 3.11 与 3.13 上做过冷启动验证，未宣称覆盖所有 3.x 版本）；
3. 一个**专门的小号** DeepSeek 账号——**永远不要用主力账号**；
4. 一个想接进来的客户端（任选其一即可）；
5. 五分钟时间和一个文本编辑器。

## 二、从零跑起来

### 2.1 环境准备

**大白话**：先确认 Python 装好了、版本够新，然后把仓库代码拿下来。

**术语**：运行时依赖被钉死在 `requirements.txt`（8 个直接依赖，均为 `==` 精确版本），用虚拟环境隔离，避免和系统里其他 Python 项目互相污染。

```bash
python3 --version        # 需要 3.11 或更新；3.11 / 3.13 已实测可用
git clone https://github.com/1515asd/deeperseekerSncMax.git
cd deeperseekerSncMax
python3 -m venv deeperseeker_env
source deeperseeker_env/bin/activate        # Windows 用 deeperseeker_env\Scripts\activate
pip install -r requirements.txt
```

逐行说明（每行卡住了看右边那一列）：

| 命令 | 作用 | 卡住了看 |
|---|---|---|
| `python3 --version` | 看版本 | 报 `command not found` → 先装 Python；版本低于 3.11 → 升级 |
| `git clone ...` | 拉代码 | 网络超时 → 换网络，或用仓库页面的 ZIP 下载再解压 |
| `python3 -m venv ...` | 建虚拟环境 | 报缺少 `venv` / `ensurepip` → 装系统包 `python3-venv` |
| `source .../activate` | 进入虚拟环境 | 提示符前应出现 `(deeperseeker_env)`；没出现说明没激活成功 |
| `pip install -r requirements.txt` | 装 8 个钉死依赖 | 装不动 → 见 7.1；不要自行改动钉死版本 |

> **为什么依赖要钉死**：`requirements.txt` 里的 8 个版本，是这个服务实际跑通「装依赖 → 冷启动 → 端点冒烟」的那套组合。上游某个包一发新版，就可能悄悄改变行为，钉死能保证你我在同一套依赖上说话。要升级，改版本号后先让 CI 的冒烟测试跑一遍再说。**别图省事把 `==` 删了**，那等于把「能跑」交给运气。

### 2.2 配置与启动

**大白话**：`.env` 就是这个程序的「设置文件」。第一次用，至少要决定三件事——**面板登录密码、客户端用的 API 密钥、监听地址**。仓库自带一份模板 `.env.example`，复制过来改就行。

**术语**：`.env` 存放环境变量（`DEEPSEEKER_ADMIN_PASSWORD`、`DEEPSEEKER_API_KEY`、`HOST` / `PORT` 等），由 `python-dotenv` 在启动时加载。完整变量清单见模板本身与主 README 的「配置」章节；本节只讲最小可用集。

```bash
cp .env.example .env     # 复制模板，随后用编辑器修改
python3 app.py
```

三个最小项的取值建议：

| 变量 | 模板里的值 | 建议你怎么改 | 不改会怎样 |
|---|---|---|---|
| `DEEPSEEKER_ADMIN_PASSWORD` | `admin` | 换成一个强密码 | 直接跑代码时只是日志告警、仍会启动；用 `docker compose` 时未设置会拒启，但设置了弱密码它也不拦，见 7.6 和第八章 |
| `DEEPSEEKER_API_KEY` | `dseeker` | 换成你自己的随机串 | 等于把服务钥匙设成公开默认值，别人也能调你的接口 |
| `HOST` | `127.0.0.1` | 只在本机用就保持；要远程访问改成 `0.0.0.0` | 改成 `0.0.0.0` 意味着暴露到网络，务必配合强密码与 HTTPS，见第八章 |

> **一个非常容易踩的点（两种钥匙别混）**：如果你**完全不设** `DEEPSEEKER_API_KEY`（删掉这行、也不挂 `.env`），服务不会回落到 `dseeker`，而是**自动生成**一把随机 `dsk-` 开头的密钥，写进数据目录的 `api_key.txt`（权限 0600，只在首次启动日志里打印一次）。这时候填 `dseeker` 会一直得到 401，要去那个文件里把真钥匙读出来。反过来，照模板复制 `.env` 时生效值就是 `dseeker`。这两种情况只能对上一个，混了就会一直 401——见 7.2。

三种运行方式：

| 方式 | 命令 | 适用 |
|---|---|---|
| 本地直接跑 | `python3 app.py` | 开发、试用、单机 |
| Docker / Podman | `cp .env.example .env` 后 `docker compose up -d` | 想长期稳定、要持久卷 |
| 免费托管平台（Pterodactyl 系） | `PORT=$SERVER_PORT python app.py` | 平台注入 `SERVER_PORT` 而非 `PORT`；`wasm/` 目录必须完整部署；`DB_PATH` 指到持久卷，否则重建容器会丢令牌池 |

> 托管平台三件事别漏：**`wasm/` 要整目录传上去**、**用 `SERVER_PORT` 兜底端口**、**`DB_PATH` 指持久卷**。这三条任一漏掉，分别表现为启动即报错、端口对不上、每次重启令牌池清空。详见 7.8。

### 2.3 登录面板

浏览器打开 `http://localhost:4000/`（远程机器就换成那台的地址），用 `.env` 里设的用户名密码登录。

- 默认 `DEEPSEEKER_ADMIN_USER` / `DEEPSEEKER_ADMIN_PASSWORD` 是 `admin` / `admin`，**务必改掉**，尤其绑到公网时——启动日志会反复提醒你。
- 登录页打不开、或一直 401，去 7.2。

面板地址里的 `4000` 来自 `PORT`；Dockerfile 的 `EXPOSE`、compose 的端口映射、`.env.example` 与两份 README 都对齐在这个端口，改端口时要一起改，否则健康检查会失效（见 7.4）。

### 2.4 添加第一个令牌

**大白话**：程序得知道「用哪个 DeepSeek 账号去聊」。这个凭证叫**令牌（token）**，从你自己的浏览器里取出来，贴进面板就行。面板首页自带完整图文教程，这里把三种方法都写全。

**术语**：令牌是 DeepSeek 网页版存在 `localStorage` 里的会话 JWT（键名 `userToken`）。服务端持有它，即可代替浏览器与会话后端通信；令牌等同于账号本体，泄露即等于账号泄露。

**第 1 步**：开一个无痕窗口登录 `chat.deepseek.com`。新设备可能要求邮箱验证码，那是官方流程，照做即可。

**第 2 步**：按设备选一种提取方式。

| 设备 | 做法 |
|---|---|
| 桌面 / Android（有开发者工具） | F12 打开控制台，执行 `JSON.parse(localStorage.getItem("userToken")).value`，把输出复制出来 |
| iPhone / iPad（Safari 书签） | Safari 不能直接跑 `javascript:`，先收藏任意页面 → 编辑该书签 → 把网址整段替换成下面的书签代码 → 在已登录的 `chat.deepseek.com` 页面点这个书签，令牌自动复制到剪贴板 |
| iPhone 快捷指令 | 面板首页教程里给了等效的快捷指令路线，效果同上 |

Safari 书签用的代码（整段复制，替换书签网址）：

```javascript
javascript:(function(){var t='';try{var r=localStorage.getItem('userToken');if(r){try{t=JSON.parse(r).value||r;}catch(e){t=r;}}}catch(e){alert('Read failed: '+e.message);return;}if(!t||t.length<20){alert('No userToken found.');return;}var a=document.createElement('textarea');a.value=t;a.style.cssText='position:fixed;left:-9999px';document.body.appendChild(a);a.select();a.setSelectionRange(0,999999);document.execCommand('copy');a.remove();alert('Copied. length '+t.length+'\n'+t.substring(0,12)+'...');})();
```

如果弹出 `No userToken found.`，说明当前页面没登录、或登录的是别的域，回到第 1 步重新确认。

**第 3 步**：面板点「添加令牌」→ 粘贴 → 保存，然后关掉无痕窗口。

**建议多加几个账号**：程序会在它们之间自动轮转，某个被限速时自动切到下一个（术语：多账号池轮转 + 自动故障转移）。只放一个号，一旦它被限速或过期，服务就直接不可用了。

> 令牌会过期，而且**什么时候过期由 DeepSeek 服务端决定，这边无法预知**。过期表现、怎么判断、怎么换，见 6.1 与 7.3。

### 2.5 接上你的 AI 工具

**大白话**：在你的客户端里填三样东西——接口地址、钥匙、模型名，然后就能像平时那样聊天了。

**术语**：客户端发标准 OpenAI / Anthropic 协议请求到本服务，服务端做协议翻译与会话管理，再与上游交互；模型名会被归一化，所以客户端里填什么 `model` 都会被映射到同一个默认模型。

OpenAI 兼容客户端（绝大多数工具用这套）：

| 填什么 | 值 | 说明 |
|---|---|---|
| 接口地址 Base URL | `http://localhost:4000/v1` | 远程机器换成那台地址；注意结尾的 `/v1` |
| API Key | `.env` 里的 `DEEPSEEKER_API_KEY` | 若服务用的是自动生成的密钥，去数据目录 `api_key.txt` 取那串 `dsk-` 开头的值 |
| 模型名 | `v4.1flash` | 唯一默认模型，原生支持视觉；客户端传别的值也会被归一化到它 |

Anthropic 兼容客户端（例如 Claude Code）：Base URL 用 `http://localhost:4000`（不带 `/v1`），其余两项相同。

`curl` 最小验证（把 `YOUR_KEY` 换成你的钥匙）：

```bash
curl -s http://localhost:4000/v1/models -H "Authorization: Bearer YOUR_KEY" | head -c 400
```

能返回一段模型列表 JSON 就说明整条链路通了；返回 401 是钥匙不对，连接被拒是服务没起来——分别去 7.2 和 7.1。

### 2.6 第一次验证：怎么确认「真的通了」

按这个顺序自查，每一步都有明确的预期：

1. **服务起来了**：启动日志没有 traceback，且访问 `http://localhost:4000/login` 返回 200（登录页）。
2. **鉴权生效**：不带钥匙访问 `/v1/models` 应返回 401；带对钥匙应返回 200。两者若颠倒，说明 `DEEPSEEKER_API_KEY` 没按你想的方式生效（回看 2.2 那个易踩点）。
3. **令牌可用**：面板里该账号状态是「正常」，不是「冷却 / 禁言 / 过期 / 隔离」。
4. **真实对话**：客户端发一句「你好」，能看到流式返回；面板用量统计出现当天记录。
5. **长一点的输入**：贴一段较长的文本，确认不空回复、不截断。

任何一步不符，去第七章对应小节。

### 2.7 本节出错速查

| 症状（大白话） | 技术原因 | 处置 |
|---|---|---|
| `python3 app.py` 立刻报错退出 | 依赖没装齐 / Python 版本过旧 / 端口被占 | 7.1 |
| 面板打不开 | 服务没监听、`HOST` 与访问地址不匹配、端口不对 | 7.1、7.4 |
| 登录一直失败 | 用了模板默认密码以外的值，或 `.env` 没被加载 | 7.2 |
| `/v1/models` 一直 401 | 钥匙用了 `dseeker` 但服务实际生成了随机 `dsk-` 钥匙（或反之） | 2.2、7.2 |
| 客户端连上但回空 | 令牌过期 / 被禁言 / 池子空了 | 7.3 |
| 每次重启令牌池都空 | `DB_PATH` 指到了临时目录 | 7.8 |

## 三、启用页面模式（Snc1，可选）

### 大白话

按第二章装完，你跑的是**老办法**：服务端自己把请求组装好发给官方。

首页说的那套「让官方页面自己发」，叫**页面模式**。它要多做三件事：**开一个开关、在浏览器装一个小脚本、让那个页面保持登录同一个账号**。三样缺一样，消息就会一直等到超时然后明确报错——**不会**偷偷退回老办法。

好处是发送这一步几乎等同于官方页面自己在发，不必跟着上游协议变更反复适配；代价是你得让一个浏览器标签页常开，且这个模式有若干限制（见 3.5）。

**它是可选的**：不开就是老办法，其余功能一点不变。

### 术语

这条路径叫 page mode。服务端只拼一个带 `q=` 与 `autosend=1` 的网址挂进待发队列，不再构造 completion 请求；配套用户脚本 `page_mode_carrier.user.js` 从 `/page_mode/pending` 领取网址，在已登录的官方页面里用 `location.href` 加载它，由页面自己把消息发出去；服务端再用只读接口 `fetch_page` / `history_messages` 把回复读回来。多轮上下文由官方页面自己的会话承担，服务端不再做会话映射与摘要滚动。

### 3.1 打开开关

编辑 `.env`，加一行后**重启服务**：

```bash
DEEPSEEKER_PAGE_MODE=1
```

- 开关只认 `1` / `true` / `yes` / `on`；`.env.example` 里有注释好的模板行，去掉行首 `#` 即可。
- 删掉这行或留空，就回到老办法，其余功能不受影响。
- 想调等待时长可加 `DEEPSEEKER_PAGE_TIMEOUT=300`（秒，默认 300）。等超时报什么、怎么调，见 3.6 和 7.9。
- **改完必须重启**，这个变量只在启动时读取。

### 3.2 在浏览器装配套脚本

`page_mode_carrier.user.js` 是用户脚本，用 Tampermonkey / Violentmonkey 之类扩展安装，只在 `https://chat.deepseek.com/*` 下运行。装之前把脚本开头两行默认值改成你自己的：

```js
const BRIDGE = GM_getValue("BRIDGE", "http://127.0.0.1:4000");  // 服务在别的机器就换成那台的地址
const KEY    = GM_getValue("KEY",    "dseeker");                 // 换成 .env 里的 DEEPSEEKER_API_KEY
```

> 若服务用的是**自动生成**的密钥（没在 `.env` 设 `DEEPSEEKER_API_KEY`），上面的 `dseeker` 就不能用——去数据目录的 `api_key.txt` 读出 `dsk-` 开头的密钥再填。这和 2.2 那个易踩点是同一件事。

`KEY` 也可以在官方页面控制台执行 `localStorage.setItem("ds_page_mode_key", "你的key")` 交给脚本兜底读取。**别把真实 API Key 提交进公开仓库**。

### 3.3 保持页面登录同一个账号

浏览器打开 `https://chat.deepseek.com/`，登录**和面板里那个令牌同一个**账号，标签页保持开着（后台标签页也行）。脚本每 4 秒取一次待发网址，取到就跳转发送。浏览器账号与面板令牌不一致，会读不到回复、一直等到超时（见 7.9）。

### 3.4 验证是否生效

```bash
curl -H "Authorization: Bearer 你的KEY" http://127.0.0.1:4000/page_mode/pending
```

| 返回 | 含义 | 怎么办 |
|---|---|---|
| `404 {"error":"page mode disabled"}` | 开关没开 | 回 3.1，确认加了 `DEEPSEEKER_PAGE_MODE=1` 且已重启 |
| `200 {"pending":[]}` | 已开启，正常 | 继续发一条消息观察 |
| `401 {"error":"Invalid API key"}` | 脚本里的 `KEY` 填错了 | 回 3.2 核对钥匙，参 7.2 |

然后随便发一条消息，看浏览器标签页是否自动跳转并发出。

### 3.5 用之前要知道的限制

- **不带附件**：图片 / 文件请求明确返回 400，页面模式只承载文字；要传附件就关掉开关走老办法（见 7.10）。
- **单条正文上限 800 字符**：超了先降级成只发最后一条用户消息，再超才返回 400，不会静默截断。
- **失败不静默回退**：脚本没装、页面没登录、账号不一致、标签页关了，都会等到超时后明确报错，不会偷偷切回老办法。这是有意设计——让你知道问题出在哪，而不是拿到一个来路不明的答复。
- **多轮记忆交给页面**：这条路径下上下文由官方页面自己的会话承担，服务端不做会话映射与摘要滚动。

### 3.6 退回老办法

删掉 `DEEPSEEKER_PAGE_MODE=1`、重启，别的都不用动。

### 3.7 读回形态对齐（可选，默认关，有效性未验证）

#### 大白话

页面模式里，「发」这一步是官方页面自己干的，可「把回复读回来」还是服务器在发请求。老代码里，读回请求穿的是我们缝的**安卓衣服**（`Dalvik/2.1.0`、`x-client-platform: android`），而同一个会话里发出去那一下，穿的是官方网页的 web 衣服。就像你本人刷脸进门、回头查记录时却递了张假身份证——不是假证做得像不像，是这张证本就不该出现：真实官方会话的读回记录里，压根没有安卓头。

这一步加一个可选开关，让**读回也穿 web 衣服**，把这张多出来的证删掉。举个具体的字：读回头的 `user-agent` 从 `Dalvik/2.1.0 (Linux; U; Android 14; Pixel 7)` 换成 `Mozilla/5.0 ... Chrome/126`，并补上真人浏览器都带的 `sec-ch-ua`、`sec-fetch-*` 这几件。

**要讲清楚的三件事**：① 它只换「形状」，令牌还是存在服务器数据库里、出口还是原来那个 IP，这两样按项目红线一律不动；② 官方认不认这套读回头、开了之后账号是不是更稳，**我们没有实测证据，不打包票**；③ 所以**默认关**，不开就还是原来那套读回头，功能一个字不变。想试试的人自己打开，合不合适自己看结果。

#### 术语

开关 `DEEPSEEKER_PAGE_WEB_READ=1`，只在页面模式（`DEEPSEEKER_PAGE_MODE=1`）下有意义。打开后，`page_chat_pipeline.py` 里 `fetch_page` / `history_messages` 两步只读 GET 改用一组 web 形态头（键集合见 `WEB_READ_HEADER_KEYS`，共 13 个键），不带 PoW / `x-hif-leim`（那是 completion 才带的）。`functions.get_headers()` 本身**一个字没动**，主路径、探活、令牌、出口全部照旧——这一步只落在页面模式自己的读回管线上。

按「无静默回退」的老规矩：打开后若读回失败，不会偷偷切回安卓头，还是走既有的明确报错 / 超时（见 3.5、7.9）。好处是你一眼能看出是这套头没生效，而不是拿到一个来路不明的答复；代价是它不会「自动帮你兜底」。

#### 怎么开 / 怎么退

在 `.env` 里 `DEEPSEEKER_PAGE_MODE=1` 旁边加一行，**重启服务**生效：

```bash
DEEPSEEKER_PAGE_WEB_READ=1
```

- 开关只认 `1` / `true` / `yes` / `on`；`.env.example` 里有注释好的模板行，去掉行首 `#` 即可。
- 删掉这行、重启，就回到原来的读回头，别的都不用动。
- **没开页面模式时这行不起作用**（读回路径压根不会走到）。

#### 出错了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 开了以后消息一直等到超时报错 | 这套 web 读回头官方没放行，或令牌 / 出口被判异常 | 先删掉 `DEEPSEEKER_PAGE_WEB_READ=1`、重启回原样，确认能读回；别在页面里反复重试 |
| 改了没反应 | 变量只在启动时读一次 | 重启服务，见 7.7 |
| 想确认到底用的哪套头 | —— | 看 `page_chat_pipeline.py` 的 `_get_json`：开关关走 `functions.get_headers()`，开走 `web_read_headers()` |
| 担心账号风险 | 这一步只是形状，不改令牌与出口 | 账号相关的如实口径见首页 README，这一项不承诺「不会被封」 |

> 这一步是把「理论上能归位的形状」归位，不是「改完就不会被封」。③ 层的令牌宿主与出口按红线不动，有效性留给实际使用去验证。

## 五、它是怎么工作的（想深入再看）

### 大白话

1. 你的工具发来一段对话 → 程序查「对号表」看之前聊过没 → 聊过就续着老会话发，没聊过就开新会话把全部历史打包发过去。
2. 每轮回复 DeepSeek 都会广播一个「消息编号」，程序记住它，下一轮接着这个编号往下聊——不靠猜，编号错了上游会拒收。
3. 对话快装不下时，旧内容自动总结成一段「前情提要」，另开新会话接着聊——你几乎察觉不到，模型也不失忆。
4. 某个账号被限速 → 自动换下一个顶上，上下文跟着一起搬过去。
5. 上游抽风（模型说到一半停了、或者干脆吐了空内容）→ 当作被打断，自动续写接着收，最多重试两次。

### 术语

1. **会话映射**：对客户端消息历史做规范化 SHA-256 签名；命中则复用上游会话（增量发送），未命中走首条全量注入路径。
2. **真实编号对接**：2026-10-31 起 DeepSeek 在流首广播 `response_message_id`，服务端用作下一轮 `parent_message_id`（旧的 +2 递增已移除）。
3. **上下文滚动压缩**（summarize-and-rollover）：逼近记忆上限（约 393K tokens）时触发摘要换血，滚动摘要 + 最近原文尾巴 + 最新消息组成新会话首条。相关阈值都在 `.env.example` 里以注释形式列出。
4. **故障转移**（failover）：401 / 403 / 429 自动隔离当前令牌，新令牌接管并完整迁移上下文。
5. **空流自动续写**：上游 502 / 静默零输出按中断处理，自动续写 ≤2 次。

## 六、常见问题

**6.1 Q：令牌会不会过期？过期了有什么表现？**
会，而且过期时间由 DeepSeek 服务端决定，这边无法预知。表现是：请求开始报鉴权类错误、面板里该账号状态变「隔离 / 冷却」、或者客户端一直回空。**处置**：重新按 2.4 提取一个新令牌，在面板里替换掉旧的；多放几个号能让它自动切走，不至于整个服务停摆。详见 7.3。

**6.2 Q：升级后老对话「失忆」了？**
2026-10-31 官方改了协议，那之前开始的对话需要一次「重新认识」。要么**等**老会话过期后重新发消息（客户端本来每次都带完整历史，发一条就全回来），要么**去官网登录、删掉那个会话**，回来发消息即可新建会话。术语上，协议变更窗口遗留的会话映射携带过期 `parent_message_id`，上游以 biz_code 26 拒收；脏会话自愈会在失败时删除映射并按首条重建。

**6.3 Q：模型说到一半就停了？**
现版本会自动续写。还遇到就重发一次，多半是上游瞬时抖动；同一条消息重发不会重复执行（幂等回放窗口保护**成功**回合，失败回合照常重试）。一直停，去 7.5。

**6.4 Q：工具调用（function calling）可靠吗？**
可靠。多格式工具调用解析 + 泄露闸门（畸形工具标记不会混进正文）+ 参数修复。把 HTML / XML 当参数值传也不会被破坏。

**6.5 Q：账号被封了怎么办？**
用小号。被封账号自动隔离出池，其余继续服务（故障转移）。**永远不要用主力账号**——自动化使用违反 DeepSeek 服务条款，封号风险自担。详见第八章。

**6.6 Q：能同时用官方付费 API 吗？**
`.env.example` 里有一组以 `DEEPSEEKER_MODE`、`DEEPSEEKER_OFFICIAL_API_KEY`、`DEEPSEEKER_OFFICIAL_BASE` 开头的「退路」配置（默认不启用）。这是一条独立的出口，和本指南默认讲的网页免费层不是一回事；具体取值和含义以 `.env.example` 注释为准，别和上面的令牌流程混用。

**6.7 Q：改了 `.env` 为什么没生效？**
绝大多数环境变量**只在启动时读取一次**。改完要重启服务才生效；`DEEPSEEKER_PAGE_MODE` 尤其是这样（见 3.1）。改了没反应先确认重启过，见 7.7。

**6.8 Q：数据会离开我的机器吗？**
默认不会。令牌池、会话、用量都在本地数据库，只有你主动设置 `DEEPSEEKER_BACKUP_TARGET` 为 `telegram` / `gist` / `file` 之一，才会有加密快照外发。详见第八章「备份与数据外发」。

## 七、故障排查手册

> **怎么用这一章**：先找和你症状最像的那一行，按「原因 → 处置」做，做完用「怎么验证好了」确认。处置里提到的章节号，回去看原理。

### 7.1 装依赖 / 启动就报错

- **症状**：`pip install -r requirements.txt` 报红，或 `python3 app.py` 立刻 traceback 退出。
- **常见原因**：① Python 版本低于 3.11；② 虚拟环境没激活，装到了系统里；③ 网络拉不到包；④ 端口 4000 已被别的程序占用；⑤ 托管平台缺 `wasm/` 目录。
- **处置**：
  1. `python3 --version` 确认 ≥ 3.11；不够就升级。
  2. 确认提示符前有 `(deeperseeker_env)`；没有就重新 `source .../activate`。
  3. 拉不动包 → 换网络或换可用的包镜像源后重装，**不要改 `requirements.txt` 里的版本号**。
  4. 端口被占 → 查占用（`lsof -i :4000` 或 `netstat -tlnp | grep 4000`），关掉占用程序，或按 7.4 换端口。
  5. 托管平台 → 确认 `wasm/` 整目录都在、`DB_PATH` 指到持久卷（见 7.8）。
- **怎么验证好了**：`python3 app.py` 不再 traceback，且日志显示开始监听；访问 `http://localhost:4000/login` 返回 200。

### 7.2 面板打不开 / 登录失败 / 一直 401

- **症状**：浏览器打不开面板；或登录一直失败；或 `/v1/models` 一直 401。
- **常见原因**：① 服务没起来（回 7.1）；② `HOST` 与你的访问地址不匹配——绑了 `127.0.0.1` 却用局域网 IP 访问；③ **两种钥匙混了**（见 2.2）：照模板 `.env` 生效 `dseeker`，但你可能没挂 `.env`、服务自动生成了 `dsk-` 钥匙，或反过来；④ `.env` 根本没被加载（放错目录、文件名不对）。
- **处置**：
  1. 先 `curl http://localhost:4000/login` 看是否 200；不是就回 7.1。
  2. 远程访问却连不上：把 `HOST` 改成 `0.0.0.0`、重启，并确认防火墙放行该端口；安全前提见第八章。
  3. 401：确认你到底属于哪种钥匙。有 `.env` 且设了 `DEEPSEEKER_API_KEY` → 用那个值；完全没设 → 去数据目录 `api_key.txt` 读 `dsk-` 开头的真钥匙。登录面板用的是 `DEEPSEEKER_ADMIN_USER` / `DEEPSEEKER_ADMIN_PASSWORD`，和这把 API 钥匙是**两回事**，别填串了。
  4. 检查 `.env` 是否在项目根目录、名字就是 `.env`（不是 `.env.txt`）。
- **怎么验证好了**：登录页能打开、登录后进得去面板；带对钥匙 `/v1/models` 返回 200、不带返回 401。

### 7.3 客户端连上但回空 / 令牌状态异常

- **症状**：请求能连到服务，但回复是空的、或报鉴权错误；面板里账号状态是「冷却 / 禁言 / 过期 / 隔离」。
- **常见原因**：令牌过期、被限速、被封禁、账号被禁言，或池子里一个可用号都没有。
- **处置**：
  1. 面板看令牌池表状态；有「隔离 / 冷却」的，先按 2.4 补一个新令牌。
  2. 多放几个账号，让轮转自动切走坏号（见 2.4 末尾）。
  3. 官方页面里手动确认该账号能不能正常发消息——如果网页版本身就发不出去，是账号侧问题，不是本服务能修的。
- **怎么验证好了**：面板里至少一个号是「正常」，发「你好」能收到流式回复，用量统计出现当天记录。

### 7.4 改端口 / 健康检查失效

- **症状**：改了 `PORT` 后容器被判 unhealthy，或 compose 里访问不到。
- **常见原因**：端口在多个地方要一起对齐——`PORT`、Dockerfile 的 `EXPOSE`、compose 的端口映射、健康检查探的 `localhost:4000`、两份 README 里的地址。只改一处就会对不上。
- **处置**：要么统一改对所有位置，要么**干脆别改端口**，保持默认 4000 最省事。远程访问用反向代理转发到 4000，比改端口安全。
- **怎么验证好了**：`curl http://localhost:4000/login` 返回 200；容器 `HEALTHCHECK` 探活通过。

### 7.5 模型答到一半停 / 一直空回复

- **症状**：输出中途截断，或整条回复是空的。
- **常见原因**：上游瞬时抽风、502、静默零输出。正常情况下服务会自动续写（见第五章），偶发一次不用管。
- **处置**：偶发 → 重发一次即可；持续发生 → 看面板「上游健康」探针，或点「立即探测」确认真的是上游问题；期间多备几个令牌让它自动切。相关的高级开关（首字节超时、空流重试阈值等）都以注释形式列在 `.env.example`，动它们之前先确认自己要改的是哪一个。
- **怎么验证好了**：连续发几条都能完整收尾；「上游健康」显示可达。

### 7.6 compose 与「默认密码」的那点区别（很容易误解）

- **症状**：以为「用了 `docker compose` 就挡住了弱密码」，或反过来「没设密码怎么还能启动」。
- **如实说清**：
  - `docker compose` 的 `DEEPSEEKER_ADMIN_PASSWORD` 用的是 `:?` 写法，含义是「**变量没设置或为空就拒绝启动**」。它**不检查密码强弱**。
  - `.env.example` 里这一行的生效值就是 `admin`。你照着 `cp .env.example .env` 之后，变量**有值**，`:?` 直接放行——所以弱密码 `admin` 是能进来的，务必自己改成强密码。
  - 用 `python app.py` 或 `docker run`（绕过 compose）时，默认 `admin` / `admin` 只会打日志告警，服务照常启动，不拦。
- **处置**：不管哪种运行方式，**都自己设一个强密码**；别指望 compose 替你把这一关。
- **怎么验证好了**：`.env` 里 `DEEPSEEKER_ADMIN_PASSWORD` 是非 `admin` 的强值，重启后用新密码能登录、旧密码登不进。

### 7.7 改了配置没生效

- **症状**：改了 `.env` 里的值，行为没变。
- **原因**：环境变量基本都是**启动时读一次**，运行中改不会热加载。
- **处置**：重启服务（`DEEPSEEKER_PAGE_MODE`、`HOST`、`PORT`、`DEEPSEEKER_API_KEY` 等均如此）；Docker 用 `docker compose up -d --force-recreate` 或重启容器。
- **怎么验证好了**：重启后按对应章节的自查步骤确认新值生效。

### 7.8 每次重启令牌池都空 / 数据不持久

- **症状**：容器或平台重建后，面板里账号全没了、用量历史清零。
- **原因**：`DB_PATH` 指到了临时目录，或托管平台没挂持久卷；Docker 场景没把数据卷留住。
- **处置**：把 `DB_PATH` 指到持久卷路径（Docker 默认是 `/app/data/deeperseeker.db`，对应命名卷），平台部署时确认该目录被持久化；`DEEPSEEKER_COOKIE_PATH` 同理。
- **怎么验证好了**：加一个令牌 → 重启 → 令牌还在、用量还在。

### 7.9 页面模式一直等到超时 / 报明确错误

- **症状**：开了页面模式后，消息不出结果，等到 `DEEPSEEKER_PAGE_TIMEOUT` 后报错。
- **原因（三样缺一不可，见第三章）**：开关没开并重启、浏览器脚本没装或 `KEY` 填错、官方页面没登录**同一个账号**或标签页被关。
- **处置**：按 3.4 的 `curl` 表逐项定位——404 回 3.1、401 回 3.2、200 但发不出就查页面登录账号与标签页是否还开着；账号不一致尤其常见。
- **怎么验证好了**：3.4 返回 `200 {"pending":[]}`，发消息能看到标签页自动跳转并送出，回复正常读回。

### 7.10 页面模式下传附件被拒

- **症状**：带图片 / 文件的请求返回 400。
- **原因**：页面模式**只承载文字**，不支持附件，这是明确限制不是 bug（见 3.5）。
- **处置**：删掉 `DEEPSEEKER_PAGE_MODE=1`、重启回老办法再传；或这次改用纯文字。
- **怎么验证好了**：关掉页面模式后同样的附件请求能正常发出。

### 7.11 备份没生成 / 开了备份却没外发

- **症状**：设了备份但看不到快照，或数据没到 Telegram / Gist。
- **原因**：默认 `DEEPSEEKER_BACKUP_TARGET=none` 什么都不做；任何非 `none` 目标都**必须**设 `DEEPSEEKER_BACKUP_SECRET`，否则加密没法做；`telegram` / `gist` 各自的 token / id 也得配齐（见第八章表格）。
- **处置**：逐项核对目标对应的变量；间隔 `DEEPSEEKER_BACKUP_INTERVAL` 默认 21600 秒（代码里最小夹到 300），别以为设了就立刻发。
- **怎么验证好了**：等一个周期后，在目标端能看到加密快照；日志无报错。

### 7.12 排查的通用顺序（上面都对不上时）

1. 服务起没起：`curl http://localhost:4000/login` 是否 200（7.1）。
2. 钥匙对不对：带 / 不带钥匙分别打 `/v1/models`（7.2）。
3. 令牌好不好：面板状态、官方网页能否手动发消息（7.3）。
4. 上游通不通：面板「上游健康」探针（7.5）。
5. 配置生效没：改过 `.env` 就确认重启过（7.7）。
6. 数据还在不：重启前后比对令牌池（7.8）。
7. 还不行，带上启动日志、复现步骤去仓库 [提 Issue](https://github.com/1515asd/deeperseekerSncMax/issues)（中英都可以）；**别把真实令牌、API Key、密码贴进 Issue**。

## 八、安全须知与数据外发

- 面板密码一定要改（默认 `DEEPSEEKER_ADMIN_USER` / `DEEPSEEKER_ADMIN_PASSWORD` 是 `admin` / `admin`）。compose 的 `:?` 只拦「没设置」，不拦「设了弱密码」，见 7.6。
- `DEEPSEEKER_API_KEY` 是你对外服务的钥匙，别用弱值，也别和自动生成的 `dsk-` 钥匙搞混（2.2、7.2）。
- 令牌 = 账号本体，不要发给任何人、不要贴进别人的面板或公开仓库。
- 自动化使用违反 DeepSeek 服务条款，封号风险自担；请勿搭建公共转发站，**永远不要用主力账号**。
- 建议只绑定本机（`HOST=127.0.0.1`）；需要远程访问时套 VPN / 反向代理 + HTTPS，别把裸服务直接暴露公网。
- 若完全不设 `DEEPSEEKER_API_KEY`，服务会生成随机 `dsk-` 密钥写入数据目录的 `api_key.txt`（权限 0600，仅首次启动日志打印一次）；此时填 `dseeker` 会一直返回 401。
- 面板里的「指纹」一栏只是备档展示，方便你自己辨认令牌来源，不会随任何请求发出。

### 备份与数据外发（默认关闭）

`ds_backup.py` 定期把数据库里的**令牌池、会话、文件索引与聊天记忆**打包，用 `DEEPSEEKER_BACKUP_SECRET` 加密后外发。默认 `DEEPSEEKER_BACKUP_TARGET=none`，什么都不离开本机；设为 `telegram` / `gist` / `file` 才有数据离开本机：

| 目标 | 必需配置 | 去向 |
|---|---|---|
| `telegram` | `DEEPSEEKER_BACKUP_TG_BOT_TOKEN`、`DEEPSEEKER_BACKUP_TG_CHAT_ID` | Telegram Bot 的 `sendDocument` |
| `gist` | `DEEPSEEKER_BACKUP_GIST_TOKEN`、`DEEPSEEKER_BACKUP_GIST_ID` | GitHub 私有 Gist（需先手动创建；未填 ID 时模块会新建） |
| `file` | `DEEPSEEKER_BACKUP_FILE_PATH` | 本机指定路径 |

- 任何非 `none` 目标都**必须**设置 `DEEPSEEKER_BACKUP_SECRET`（建议 24+ 字符随机串），快照加密后才上传；密码丢了备份就解不开。
- `DEEPSEEKER_BACKUP_INTERVAL` 默认 21600 秒（6 小时），代码里最小夹到 300 秒。
- 全部备份变量都列在 `.env.example`。Gist token 需要 `gist` 权限，Bot Token 与加密密码都别提交进仓库。出问题时见 7.11。
