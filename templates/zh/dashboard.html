添加账号

⚠️ 使用模型说明（2026-11-07 实测更新）：令牌出生在你自己的设备上，使用在服务器。
11 月起上游风控大幅收紧，今天的真机实测结论：安卓协议登录现在必须携带安卓真机数美 SDK 生成的设备指纹（约 89 字符），不填、乱填、或用浏览器取到的短格式一律被拒（RISK_DEVICE_DETECTED）——所以没有安卓设备的用户（含 iPhone）走不了安卓协议登录；邮箱登录在新设备上会强制邮箱验证码。实测全程可跑通的路径：Safari 完整登录（含邮箱验证码）→ javascript 书签从页面取令牌（见下方方法 B）。
风险提示：第三方实测反馈「昨晚起 3-4 次请求即掉令牌」，单次请求能通不代表长期可用；能否完全避免封号尚无定论，请控制使用强度、只用小号，账号被封无法承担责任。

方式一 · 在自己设备上登录（需要安卓真机指纹）：用登录工具向 DeepSeek 发送一次官方安卓 App 同款登录请求（走你自己的家庭网络），令牌随登录结果直接返回——出生即安卓，与桥的使用形态一致。2026-11-07 实测：此路必须能提供安卓真机的数美指纹，电脑/iPhone 取不到，取不到就用方法 B。

方法 A · 电脑（Windows / Mac / Linux，跑一次脚本）
  1. 装好 Python（没有的话去 python.org 装一个，勾选 Add to PATH）
  2. 下载登录脚本：tools/login_once.py（仓库里，右键另存为）
  3. 运行 python login_once.py，按提示输入账号、密码，可选设备指纹
  4. 输出的令牌复制，贴到下方「贴入令牌」表单

在公司/校园网或 VPN 下运行可能被 WAF 拦（脚本会自动检测并提示），换家庭宽带或手机热点即可。

方法 B · iPhone / iPad（不用电脑，实测可行：Safari 登录 + 书签取令牌）

为什么不是快捷指令？原来的快捷指令方案模拟安卓 App 登录，但上游现在要求登录请求必须携带安卓版数美 SDK 生成的设备指纹（安卓手机上才能生成的 89 字符串），iPhone 网页上取到的是另一种格式，怎么填都会被拒（RISK_DEVICE_DETECTED）。所以放弃快捷指令，改用下面这套——2026-11-07 在真 iPhone 上完整实测通过的：

  1. iPhone 的 Safari 打开 chat.deepseek.com，用账号密码正常登录。第一次在这台设备登录会要求邮箱验证：DeepSeek 发一串验证码到你的注册邮箱，去邮箱把码抄出来填进去，登录才算完成。这是官方流程，正常走即可
  2. 登录成功、能看到聊天页面后别关这个页面。点 Safari 底部的「分享」按钮 → 选「添加书签」，先随便存一个书签
  3. 打开 Safari 的书签列表 → 「编辑」→ 点刚才那个书签 → 把网址一栏整个替换成下面这段（整段复制，一个字符都别少）：
    javascript:prompt('令牌如下',JSON.parse(localStorage.getItem('userToken')).value)
    改完保存
  4. 回到 chat.deepseek.com 那个页面（必须停在这个页面），从书签列表里点一下刚才改好的书签。屏幕会弹出一个框，里面就是你的令牌——长按全选复制
  5. 把令牌贴到下方「贴入令牌」的表单，完成

说明：第 4 步必须停在 chat.deepseek.com 页面上点书签才有效；如果弹出来是 null 或报错，说明页面没登录成功（回第 1 步），或 Safari 的 JavaScript 被关了（设置 → Safari → 高级 → 打开 JavaScript）。这个令牌来自你自己手机上的完整官方登录（含邮箱验证码），是你账号的钥匙，不要发给别人。风险提示照旧：会话是网页形态出生的，暂不能保证长期不被风控波及，建议用小号。

方法 C · 安卓（Termux / HTTP Shortcuts）

命令行（推荐）：安装 Termux → pkg install curl -y → 下载仓库里的 tools/deepseek-login.sh → bash deepseek-login.sh，按提示输入账号密码，令牌随结果输出。

图形化（备选）：安装开源应用 HTTP Shortcuts → 导入 → 从 cURL 命令导入，粘贴 tools/deepseek-login.sh 里的 curl 段，再把账号密码改成自己的（建议用 App 变量）→ 桌面小组件一键登录。

设备指纹（2026-11-07 实测更新：只有安卓真机能生成有效指纹）
真实安卓 App 登录时携带数美 SDK（安卓原生版）生成的设备指纹（约 89 字符 base64）。当天完整实测结论：
  • 登录请求现在必须携带 device_id 字段——缺了直接 422 被拒（连账号都不校验）
  • 空值 / 随机伪造值 → RISK_DEVICE_DETECTED（biz_code 11）
  • 浏览器版数美 SDK 生成的指纹（约 31 字符短 ID）同样被拒（11）——包括电脑 Chrome 和 iPhone Safari 取到的。所以旧版教程里「浏览器 F12 取指纹」的方法已失效
结论：没有安卓真机，就无法生成能通过校验的指纹，安卓协议登录（方法 A / 安卓命令行）也就走不通。这正是本面板改推「Safari 网页登录 + 书签取令牌」（方法 B）的原因。手头有安卓真机的用户仍可走方法 A：在安卓手机浏览器打开 chat.deepseek.com（不登录），页面控制台执行 SMSdk.getDeviceId()（输出 undefined 就等几秒再执行一次），取到的指纹随登录工具填入。

贴入令牌：把登录工具输出的令牌粘贴到这里（不要带引号）。令牌等同于你的 DeepSeek 账号，只贴进自己的面板。
设备指纹是可选的备档信息：面板只把它记录下来并检查格式，不会用它发任何请求。从安卓真机/登录工具拿到数美指纹（约 89 字符）可以填；手机网页取到的短指纹也能填（会标注为「网页格式」，实测它无法通过安卓登录，仅备档）。

令牌有效期不固定，失效就再跑一次登录工具换新的，旧的删掉即可。面板「检测」按钮可查看每个令牌的真实状态（正常 / 禁言到几点 / 已作废）。
