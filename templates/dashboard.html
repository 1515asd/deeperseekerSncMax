Record / update a token's device fingerprint (optional, for display only)

This is record-keeping only: the panel logs and annotates the format so you can tell tokens apart. Leaving it empty is perfectly fine — chat requests carry the protocol-required fields as usual (upstream doesn't target this either), and filling it or not makes no difference. Save with it empty to clear.

When do tokens expire? No fixed schedule — DeepSeek's server decides, and there's no way to know in advance. After expiry clients report 401 or 503 No tokens available.
Can't tell expired from muted? Hit "Check all tokens" to ask DeepSeek each token's real status. You can also sign in at chat.deepseek.com to verify: the site asks you to log in again = expired; sending a message pops a mute notice = muted; chat works fine = false positive, just hit "Restore".
Feel free to try: the "Restore" button is safe — if the token is really dead it gets quarantined again automatically, no harm done.

When a client request asks for "high-intensity thinking" (e.g. reasoning_effort=max), an instruction is added telling the model to take its time, verify from multiple angles and check step by step — deeper answers, a bit slower, more tokens. When off, the model answers entirely its own way. Takes effect immediately, no restart needed.

Add an account

✨ This release takes a brand-new approach: the sending part has moved.
After half a day of work, the author turned the earlier abstract problem fully concrete — one change of angle, and the long-standing pains around login, disconnects and empty replies are eliminated at the method level instead of being patched one by one. All you need to do: log in to DeepSeek normally in your browser, grab the token and paste it into the panel.
The usual risk note: keep usage intensity in check and use burner accounts only — no one can be held responsible for banned accounts.
Recommended · browser login + bookmarklet to grab the token (works on desktop, iPhone and Android, verified)
  1. Open chat.deepseek.com in Safari / Chrome and sign in normally with your account. The first time you may be asked for email verification: copy the code in and continue — that's the official flow
  2. Once signed in, don't close the page.
    • Desktop: run JSON.parse(localStorage.getItem("userToken")).value in the F12 console, copy the output
    • iPhone / iPad: tap Safari's "Share" at the bottom → "Add Bookmark" to save any page → "Edit" in the bookmark list → replace that bookmark's URL with:
      javascript:prompt('Your token',JSON.parse(localStorage.getItem('userToken')).value)
      then go back to chat.deepseek.com (you must be on that page), tap the bookmark, and the popup holds your token
  3. Paste the token into the "Paste token" form below — done

iPhone bookmark doesn't pop anything = sign-in didn't succeed (back to step 1) or Safari JavaScript is off (Settings → Safari → Advanced → enable). Your token is the key to your account — only paste it into your own panel.

Paste token: paste the token you grabbed here (no quotes). The token is equivalent to your DeepSeek account.

The fingerprint field is optional: it's for display and record-keeping only, leaving it empty is perfectly fine, upstream doesn't target it — feel free to skip. Tokens don't last forever; grab a fresh one and swap it in when one dies.

Appendix · desktop script login (Windows / Mac / Linux, run one script)
  1. Install Python (python.org, tick Add to PATH)
  2. Download the login script: tools/login_once.py (in the repo, right-click → save as)
  3. Run python login_once.py and enter your account and password when prompted
  4. Copy the token it prints and paste it into the "Paste token" form above

On corporate/campus networks or a VPN the WAF may block the script (it detects and warns by itself); switch to a home connection or a phone hotspot.

Appendix · Android (Termux / HTTP Shortcuts)

Command line: Termux → pkg install curl -y → download tools/deepseek-login.sh → bash deepseek-login.sh.

GUI: HTTP Shortcuts → import the curl snippet from a cURL command, change the account and password to yours (App variables recommended) → home-screen widget for one-tap login.

Appendix · about the device fingerprint (optional, display only)
Upstream's login endpoint validates device fingerprints for Android-protocol logins (only the format produced by the Android native SDK is accepted; the short browser format gets rejected) — that only affects the choice of login method. The fingerprint field in the panel has nothing to do with it: it's display/record-keeping only, and the panel never sends any request with it. Leaving it empty is perfectly fine, upstream doesn't target it — feel free to skip.
